# مركز آيت تقرين النفسي — Centre Psy Aitigrine

منصة ويب متكاملة لمركز استشارات نفسية وأرطوفونية — **الإصدار 3.24.1**

- خمس لغات كاملة: العربية · الفرنسية · الإنجليزية · التركية · الإسبانية (تفعيل/تعطيل من الإعدادات)
- تطبيق صفحة واحدة (Next.js 16) + MongoDB (Mongoose) + GridFS للوسائط

## التشغيل السريع

```bash
npm install          # تثبيت الحزم
npm run mongo        # تشغيل MongoDB المحلي (بيئة معاينة)
npm run dev          # الموقع على http://localhost:3000
```

للإنتاج: `npm run build` ثم `npm start` مع رابط MongoDB خارجي في `.env`.

### ملف البيئة `.env`

انسخ `.env.example` إلى `.env` وعدّل القيم:

| المتغير | الوصف |
|---|---|
| `MONGODB_URI` | رابط قاعدة البيانات (Atlas للإنتاج) |
| `AUTH_SECRET` | عبارة سرية طويلة لتوقيع التوكنات |
| `ADMIN_PHONE` / `ADMIN_PASSWORD` | بوابة الإدارة (يُنشأ الحساب تلقائياً) |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | دخول Google (اختياري — v3.9) |
| `NEXT_PUBLIC_CENTER_WHATSAPP` | رقم واتساب احتياطي إذا خلت إعدادات المركز (v3.9) |
| `PUBLIC_BASE_URL` | عنوان الموقع العام (للـ OAuth redirect) |

### ★ إصلاح خطأ `redirect_uri_mismatch` (دخول Google)
هذا الخطأ يعني أن **رابط العودة المسجّل في Google Console لا يطابق حرفياً** الرابط الذي يستعمله الخادم. الحل الدقيق:

1. ادخل بحساب الإدارة → **إعدادات المركز → تبويب «الأدوات» → بطاقة «دخول Google»**
2. **انسخ** رابط العودة المعروض (نمطه: `https://<your-domain>/api/auth/google/callback`)
3. في [Google Cloud Console](https://console.cloud.google.com) → **APIs & Services → Credentials → OAuth 2.0 Client ID** → خانة **«Authorized redirect URIs»** أضف الرابط **حرفياً** (بدون شرطة مائلة في النهاية، بدون فراغات، نفس `http/https` ونفس النطاق والمنفذ)
4. احفظ في Google ثم أعد المحاولة — يستغرق التغيير أحياناً دقائق معدودة للتفعيل
5. إن كان الموقع خلف نطاق عام فعّل أيضاً `PUBLIC_BASE_URL=https://<your-domain>` في `.env` لضمان ثبات الرابط

> ملاحظة: أي اختلاف (حتى منفذ تجريبي مثل `:3100` أو `localhost` مقابل نطاق عام) يسبب نفس الخطأ — سجّل كل رابط تستعمله فعلياً (التجريبي والإنتاجي معاً).

## الجديد في الإصدار 3.24.1 — إصلاحات كثيفة بعد الاستعمال الفعلي

1. **مفاتيح المرور (Passkeys)**: إصلاح جذري لفشل «تعذر تفعيل المفتاح» — التحدي الوارد من المتصفح بترميز base64url بينما القاعدة تحفظ السلسلة الأصلية؛ يُفكّ الترميز الآن قبل المطابقة (`takeChallengeSmart`) مع رسائل خطأ دقيقة (انتهاء الصلاحية مقابل فشل التحقق).
2. **صفحة الحسابات**: تعديل الأخصائي/العميل بكائن كامل لم يعد يفشل — سن وجنس العميل ونظام الأجر والراتب الثابت تُتجاهل بهدوء على غير دور هدفها (نمط زمرة الدم) والقيم الفعلية وحدها تُرفض؛ وكذلك نافذة تعديل العميل أعيدت للحياة (مكوّن أيقونة غير معرّف كان يُسقطها).
3. **الموارد البشرية**: بلا إغلاق تلقائي للبطاقات بعد أي عملية (تحديد الموظف في مرجع ثابت)، الحضور بتعديل محلي + **حفظ يدوي دفعي** واحد (زر بعدّاد التغييرات، التقويم لا يغلق أبداً، حفظ صامت عند التبديل)، بطاقة الموظف كلها قابلة للنقر، **شارة الدفعات المقدمة** في البطاقة، تعديل الإجازة والدفعة (زر تعديل لكل صف) وحقل «النوع/السبب» الاختياري، الحذف يعمل فعلياً من قاعدة البيانات (المعرّفات تُعاد في ورقة الراتب).
4. **ورقة الراتب الاحترافية**: صفحة واحدة بلا صفحات فارغة (بوابة في جذر المستند)، اسم ملف PDF يحمل اسم الموظف والشهر، اللوغو، جدول هوية أنيق، المستحقات مقابل الخصومات، الصافي المظلل، ملخص الحضور، الملاحظة القانونية (قسط اليوم = الأساس ÷ 26 وفق قانون العمل الجزائري 90-11)، توقيع المستفيد وصاحب العمل، واسم المركز والعنوان يترجمان حسب لغة الوثيقة.
5. **محلل النطق**: أخطاء الميكروفون تفصيلية حسب السبب (إذن مرفوض مع توجيه الإصلاح / لا ميكروفون / مستعمل ببرنامج آخر / سياق غير آمن / متصفح غير مدعوم)، بنك الكلمات العلاجية **بخمس لغات** (الحرف والكلمة يظهران بلغة الواجهة والكلمة العربية تبقى مرجع النطق والتحليل)، والنتائج والتوجيهات تُصاغ بلغة الأخصائي.
6. **الملف الشخصي**: العميل يرى ويعدّل سن وجنسه من ملفه مع شارتَي عرض في الرأس.
7. **أيقونات وترجمة**: أيقونة الموارد البشرية أصبحت Briefcase (بلا تكرار مع الحسابات)، و34 مفتاحاً جديداً × 5 لغات مع تصحيح عبارات ورقة الراتب.

## الجديد في الإصدار 3.24.0 — نظام أجر مزدوج + موارد بشرية كاملة + Passkeys + محلل نطق ذكي + تفاصيل التقويم والعملاء

### ١) نظام أجر مزدوج لكل أخصائي (طلب صاحب المركز)
- الإدارة تختار لكل أخصائي على حدة: **عمولة لكل جلسة منتهية** (كما في v3.23) أو **راتب شهري ثابت**.
- في نظام الراتب: تُهمل النسبة في المستحقات (صفر)، يظهر شارة «راتب ثابت» في الأجور والحسابات، وصفحة «أرباحي» تعرض الراتب الشهري وإحصائيات الجلسات للاطلاع فقط — والراتب يُصرف عبر نظام الموارد البشرية.

### ٢) نظام إدارة وتسيير الموارد البشرية — HR كامل (للإدارة)
- **الموظفون:** الأخصائيون والمساعدة وعاملة التنظيف والحارس وغيرهم — حتى من لا يملك حساباً في الموقع، مع استيراد تلقائي من الحسابات (الأخصائيون بنظام الراتب براتبهم + المساعدة براتبها الافتراضي من الإعدادات).
- **الحضور والغياب:** شبكة شهر تفاعلية — نقرة تُبدّل: غياب ← إجازة ← عطلة ← حذف؛ ما لا يُسجَّل يُعد حاضراً.
- **الإجازات:** مدفوعة/بدون أجر — بدون أجر تُحسب غياباً في الخصم تلقائياً.
- **الدفعات:** دفعة مقدمة (acompte) / صرف الراتب / مكافأة / خصم إداري — باسم المصروف وتاريخه.
- **الاحتساب الشفاف:** قسط اليوم = الأساس ÷ 26؛ الصافي = الأساس − خصم الغياب − الخصومات + المكافآت؛ المتبقي = الصافي − الدفعات المقدمة − المصروف.
- **وثائق الرواتب:** ورقة راتب احترافية قابلة للطباعة لكل موظف/شهر (بنظام طباعة الوثائق القائم).

### ٣) تقويم الأخصائي — تفاصيل أعمق لكل موعد
بعد الضغط على أي يوم تفتح الأجندة ببطاقة أغنى لكل موعد: نوع الخدمة + **هاتف العميل (اتصال بنقرة)** + **سن العميل** + **جنسه** — نظرة مسبقة قبل الجلسة، بتلقيف آمن على الهاتف.

### ٤) سن وجنس العميل — ربط شامل
- عند إنشاء حساب عميل (تسجيل ذاتي + إكمال Google + الإدارة + المساعد): حقل **العمر** + قائمة منسدلة للجنس (ذكر/أنثى) — اختياريان.
- يظهران في: تفاصيل التقويم، قائمة الحسابات، قائمة مرضى الأخصائي، وأرباحي؟ لا — في الملف الشخصي وقوائم العملاء — مع تعديلها من الإدارة/المساعد/الأخصائي المعالج.

### ٥) نافذة الإثبات الاجتماعي — حلة جديدة أنيقة
إطار متدرج بالهوية + شارة بأول حرف من الاسم + تفاصيل أكثر **دون أي كشف للهوية**: طريقة الجلسة (حضورية/عن بُعد) وموعدها (اليوم/غداً/التاريخ + الساعة) أو انطلاق التكوين — بنفس قواعد الخصوصية والتوقيت السابقة حرفياً.

### ٦) تسجيل الدخول بمفاتيح المرور (Passkeys)
- دخول بلا كلمة مرور: بصمة الإصبع / ملامح الوجه / رمز قفل الشاشة (WebAuthn — @simplewebauthn).
- زر «الدخول بالبصمة» في بوابتَي العميل والأخصائي + إدارة المفاتيح من «ملفي الشخصي» (إضافة/حذف/حالة المزامنة).
- rpID وorigin يُشتقان من ترويسات الطلب — يعمل على النطاق الرسمي والمعاينات وlocalhost بلا إعداد. كلمة المرور والدخول بGoogle كما هما — لا شيء تغيّر.

### ٧) محلل النطق الذكي — AI Speech Analyzer (للأخصائي)
- تسجيل صوت المريض (غالباً طفل) وهو ينطق كلمة مستهدفة من **بنك كلمات علاجية** (16 حرفاً × 4 كلمات) أو كلمة مخصصة.
- تحليل فوري بثلاث طبقات: تحويل الكلام لنص (ASR) ← مقارنة حتمية للمخارج بتطبيع عربي ← تحليل ذكاء اصطناعي بسياق أرطوفوني يعطي الاشتباه المبدئي (لثغة/تأتأة/حذف/إبدال/تشويه) وشدته وملاحظات المخارج وتوجيهات مقترحة — بJSON صارم.
- إن تعذر الذكاء الاصطناعي يرجع التحليل الحتمي وحده — الميزة لا تتوقف أبداً، والنتيجة مبدئية للتوجيه فقط.

### ٨) ضمانات الجودة
- ترجمة كاملة لكل المفاتيح الجديدة في الخمس لغات — وفحص آلي يثبت: **1088 مفتاحاً مستعملاً وصفر مفقود**.
- تصحيح «الجلرات ← الجلسات» في التعليقات + مراجعة مفاتيح v3.23.
- اختبار E2E موسّع: **79 فحصاً ناجحاً** على خادم إنتاجي محلي (كل سير v3.23 + الجديد كله + الحجب والخصوصية + رؤوس كاش).
- تجاوب كامل على الهاتف: كل الشبكات الجديدة تتراص (grid-cols-7 مضغوطة دوماً) وبلا تداخل.

## الجديد في الإصدار 3.23.1 — إصلاح واجهة أرباحي + خفض Fast Origin Transfer على Vercel

### ١) إصلاح تشوّه أسماء الأشهر في صفحة «أرباحي»
- **السبب الجذري:** صف الشهر كان `flex-1` بأساس صفر داخل صِف flex-wrap؛ عناصر الشريط (شارة الجلسات + مجموع الجلرات + المستحقات) بعرضها الطبيعي تسحب المساحة كلها على الهاتف فينضغط اسم الشهر إلى عرض أقل من كلمة → تتكدس حروفه عمودياً وتتشوه البطاقة.
- **العلاج:** إعادة بناء الصف — اسم الشهر في **سطر مستقل كامل العرض على الهاتف** والعناصر الرقمية تلتف تحته بأمان، وفي `sm+` يعود الصف الموحد مع دفع الإحصاءات للطرف الآخر (`sm:ms-auto`). لا انضغاط ممكن على أي مقاس.
- **تحسين إضافي:** ملصقات محور الرسم البياني الأفقي صارت **أسماء أشهر مختصرة** (`month: "short"`) بدل قص أول كلمة يدوياً — أضيق وأكثر ملاءمة للشاشات الصغيرة بكل اللغات (nov. / Kas / nov…).

### ٢) خفض Fast Origin Transfer (Vercel) دون أي تغيير وظيفي
كاش الحافة `PUBLIC_EDGE_CACHE` (نمط v3.17 القائم: `s-maxage=60, stale-while-revalidate=300, max-age=0`) — يُخدَّم المسار من الـ CDN للزوار المتكررين بلا استدعاء الدالة، والتعديل الإداري يظهر خلال ≤60 ثانية كحد أقصى:
- **`GET /api/settings`** — أكثر مسار استدعاءً في الموقع (كل زائر في كل تحميل صفحة، وبحمولة الشعار والوسائط) — كان بلا كاش.
- **`GET /api/team`** — فريق الرئيسية بصور base64 ثقيلة — كان بلا كاش.
- **`GET /api/quotes`** — عبارات «لحظة اطمئنان» — كان بلا كاش.
- المسارات العامة الأخرى كانت مغطاة منذ v3.17–v3.21 (specialists/services/articles/pages/media/share-image) — لم تُلمس.
- **الحرص على الصحة:** لم يُضف كاش إلا لمسارات GET **بلا أي مصادقة وباستجابة متطابقة لكل الزوار**؛ المسارات المتغيرة حسب المستخدم (earnings/payroll/reports/dashboard/…) تبقى بلا كاش تماماً كما هي — تحقق فعلي برؤوس الاستجابات + اختبار E2E كامل 37/37.

## الجديد في الإصدار 3.23.0 — الأجور والمستحقات + تقويم الأخصائي + التقارير المالية + حجب صفحات المساعد

### ١) نسب الأخصائيين ومستحقاتهم الشهرية
- **حقل النسبة (%):** الإدارة تضبط نسبة كل أخصائي من كل جلسة (0–100%) من نموذج الحسابات — تختلف من أخصائي لآخر، وتظهر كشارة في قائمة الحسابات.
- **صفحة «أرباحي» (للأخصائي فقط):** بطاقات حية — النسبة، جلسات الشهر، مستحقات الشهر، الإجمالي الكلي + رسم مستحقات آخر 6 أشهر + جدول شهري مفصّل.
- **المعادلة الشفافة:** المستحقات = (سعر الجلسة − الخصم) × النسبة — للجلسات **المنتهية** فقط. نقطة `/api/earnings` محصورة خادمياً بدور الأخصائي.

### ٢) تقويم المواعيد (Calendar Sync) — ترقية صفحة «مواعيدي» للأخصائي
- **عرض شهري:** شبكة الشهر مع نقاط ملوّنة بأعداد الحالات في كل يوم (قيد الانتظار / مؤكد / منتهي / ملغي) والنقر على أي يوم يفتح أجندته.
- **عرض أسبوعي:** أعمدة الأيام السبعة بمواعيد كل يوم (مكدسة تلقائياً على الهاتف).
- **عرض يومي:** أجندة كاملة ببطاقات الحالة وإجراءات فورية (تأكيد / إنهاء / إلغاء).
- مفتاح ألوان موحّد مع شارات القائمة، تجاوب كامل (هاتف/حاسوب)، ودعم RTL/LTR — مع بقاء عرض القائمة الكلاسيكي بخيار التبديل.

### ٣) تغيير الأخصائي المكلف بالموعد (الإدارة والمساعد)
- زر «تغيير الأخصائي» على كل بطاقة موعد + نافذة اختيار الأخصائي الجديد.
- تحقق خادمي كامل: الأخصائي الجديد مفعّل، ويستقبل فعلاً في توقيت الموعد من أوقاته المحفوظة، وبلا تصادم فتحة نشطة (حماية الفهرس الجزئي كملاذ أخير).
- إشعارات خمس لغات لكل الأطراف: العميل يتعرف على أخصائيه الجديد، الأخصائي الجديد يُكلَّف، الأخصائي السابق يُبلَّغ، والملخص الإداري في سجل التدقيق.

### ٤) حجب لوحة القيادة وإعدادات المركز عن حساب المساعد
- **القائمة والتنقل:** الصفحتان متاحتان للإدارة فقط (`NAV_ITEMS` + `ROLE_IMPORTANT`)، والشريط السفلي يتكيف تلقائياً.
- **الحرس المزدوج:** `app-shell` يعيد المساعد للرئيسية عند أي وصول مباشر بالرابط، وواجهتا dashboard/settings تعرضان شاشة «غير مصرّح» احتياطاً.
- **الخادم أيضاً:** `/api/stats` لم يعد يعيد بيانات لوحة القيادة إلا للإدارة (كان يعود للطاقم معاً).
- **بطاقة «الخدمات الأكثر طلباً» أصبحت دائرة نسب مؤية (Donut):** النسبة المئوية لكل خدمة، الإجمالي في مركز الدائرة، وقائمة تفسيرية بأسماء الخدمات **كاملة بلا أي اقتصاص (لا «…»)** تتلف بالكلمات وتتوزع بدون تداخل — تجاوب كامل.

### ٥) الاحتساب التلقائي للأجور والمستحقات (الإدارة فقط)
- صفحة **«الأجور والمستحقات»**: اختيار الشهر → لكل أخصائي: الجلسات المنتهية × نسبته = مستحقاته (تلقائي من المواعيد، بلا أي إدخال يدوي).
- **راتب المساعدة الثابت قابل للتعديل لكل شهر:** الراتب الأساسي + أيام الغياب + قسط الخصم اليومي → الخصم والصافي يظهران حياً أثناء التحرير (غياب المساعدة يخفض المبلغ تلقائياً)، مع ملاحظة إدارية اختيارية.
- **الراتب الثابت الافتراضي** يُحفظ في إعدادات المركز ويُستخدم لأي شهر جديد بلا تسوية — تعديله لا يمس الأشهر المحفوظة.
- الإجمالي العام = مستحقات الأخصائيين + صافي المساعدة. محرّك مشترك `src/lib/payroll.ts` يستعمله المسارِي `/api/payroll` (GET/PATCH) و`/api/reports`.

### ٦) التقارير المالية والإدارية (الإدارة فقط)

## الجديد في الإصدار 3.21.3 — إصلاح خطأ E11000 عند تأكيد الحجز

**السبب الجذري**: كان فهرس المواعيد الفريد `{ date, time, specialistId }` فريداً **بغضّ النظر عن حالة الموعد** — فالموعد **المكتمل أو الملغى** كان يحجب فتحته (نفس اليوم + نفس التوقيت + نفس الأخصائي) للأبد. وبما أن فحص التصادم وقائمة «الأوقات المحجوزة» في الواجهة يعتبران المكتمل/الملغى **متاحاً**، كان الحجز الجديد يمرّ بكل الخطوات ثم يُرفض في اللحظة الأخيرة بخطأ قاعدة بيانات خام أمام العميل. ولهذا ظهر اليوم رغم أن الموقع كان يعمل — يكفي وجود موعد مكتمل/ملغى سابق بنفس الفتحة.

**الإصلاح (٣ طبقات محصّنة):**

## الجديد في الإصدار 3.19.0 — زمرة الدم: إلزام عند التسجيل + صلاحيات دقيقة + ظهور في الملف الطلبي والوثائق

> طلب صاحب المركز: «إضافة حقل لاختيار زمرة الدم إجبارياً عند إنشاء حساب عميل، وللمسجلين من قبل إمكانية التعديل والإضافة من الأدمين والمساعد والأخصائي المعالج — تضاف في الملف الطلبي وتظهر في الوثائق إلى جانب معلومات العميل». نُفِّذ بحروفه مع أقصى جراحة:

- **إلزامية عند إنشاء حساب عميل**: قائمة اختيار من الفصائل الثماني العالمية (`A+ A- B+ B- AB+ AB- O+ O-` — تُخزَّن وتُعرض بصيغتها الطبية الموحدة `dir=ltr`) في نموذج التسجيل الذاتي، وأيضاً في **نافذة إكمال حساب Google** الإلزامية (الرقم + الزمرة معاً قبل الحفظ) — الخادم يرفض التسجيل بدونها (400) أو بقيمة غير صحيحة
- **للمسجلين سابقاً — ثلاثة مسارات تعديل بلا تسجيل جديد**:
  1. **الإدارة**: من نموذج تعديل الحساب (قسم بيانات العميل) مع شارة زمرة على بطاقة الحساب
  2. **المساعد**: زر «تعديل» صار متاحاً له بنمط مقيّد جديد — **زمرة الدم والتفعيل فقط** (تنبيه صريح داخل النافذة، لا اسم ولا هاتف ولا كلمة مرور) — الخادم يرفض أي حقل آخر (403) وكل تغيير زمرة يُدوَّن في سجل التدقيق
  3. **الأخصائي المعالج**: من **الملف الطلبي** (قسم الهوية) لمرضاه فقط — الحفظ يمر عبر `/api/records` بنفس قيود الوصول القائمة (مرضى المعيَّن لهم أو أصحاب مواعيد سابقة معه) — 403 لأي مريض خارج ملفاته
- **الظهور في كل مواضع معلومات العميل**: بطاقة الحساب (شارة وردية بأيقونة قطرة) · قائمة المرضى · **الملف الطلبي** (قسم الهوية) · **الوثائق الأربع المطبوعة** (سطر «يخص: الاسم — العمر — زمرة الدم: X») · «ملفي الشخصي» للعميل (عرض فقط)
- **حمايات دقيقة**: العميل لا يعدّل زمرة دمه بنفسه بعد إنشاء الحساب (403 مع رسالة تُسمّي من يملك التعديل) — غير حسابات العملاء مرفوض (400) — الفصائل محصورة بـ enum خادمي (`src/lib/blood.ts` مصدر موحّد) — الحقل اختياري في القاعدة للمسجلين سابقاً (لا إجبار رجعي ولا مساس ببيانات قائمة)
- **ترجمة كاملة ×5** (AR/FR/EN/TR/ES — فحص audit-keys: صفر نواقص) وتجاوب كلي على الهاتف (390px بلا أي فيض أفقي — مُتحقَّق عليه بصرياً)
- **الاختبارات**: 29/29 اختبار API ناجح (الإلزام/الصلاحيات الثلاثة/الرفوضات/العرض/الانحدار) + تحقق متصفح كامل AR وFR لكل التدفقات الثلاثة

- **الصلاحيات**: الإدارة والمساعد يرون التبويب ويديرون الوسائط — العميل 403 والمجهول 401 (مُختبَر فعلياً)

### كيف تستخدمها لتنحيف قاعدة بياناتك (92MB ← أقل بكثير)

1. افتح **إعدادات المركز ← الوسائط المخزنة** — راجع القائمة من الأكبر

4. الفيديوهات الطويلة تبقى أثقل عنصر — يُفضل إبقاؤها قصيرة
5. الفواتير PDF صغيرة ومحمية — لا تقلق منها

## الجديد في الإصدار 3.17.0 — تحسين استهلاك النطاق على الاستضافة (Vercel)

> سبب هذا الإصدار: توقف الموقع عند تجاوز حد **Fast Origin Transfer** المجاني على Vercel (100GB/شهر).
> هذا الحد يقيس كل بايت تُخرجه دوال السيرفر (APIs والوسائط) إلى شبكة Vercel — وقد كان المشروع يخدم كل شيء عبر الدوال بلا تخزين حافة. الإصلاحات كلها في طبقة الخدمة — **لا أي تغيير بصري أو وظيفي على المستخدم**:

- **★ تخزين حافة كامل للوسائط** (`/api/media/<file>`): أسماء الملفات فريدة أبداً لا تُستبدل، لذا أُضيف `s-maxage=31536000 + immutable + stale-while-revalidate` — بعد أول طلب لكل ملف في كل منطقة تخزّنه Vercel Edge وتخدمه من الـ CDN **بلا استدعاء الدالة ولا قراءة GridFS** — هذا هو الإصلاح الجذري الأكبر (`max-age` وحده كان يخزّن في متصفح الزائر فقط ولا يفيد الزوار الجدد ولا الروبوتات)
- **كاش حافة قصير للمسارات العامة** التي لا تختلف باختلاف المستخدم (60 ثانية + تجديد خلفي): `services` · `specialists` · `articles` (القائمة العامة فقط) · `pages` — الزيارات المتكررة والروبوتات تُخدم من الـ CDN، وتعديلات الإدارة تظهر خلال ≤60 ثانية كحد أقصى (سلوك CDN قياسي)
- **⛔ بلا كاش عمداً** على المسارات المتغيرة حسب المستخدم: `courses` (`enrolledByMe`) · `testimonials` (أسماء الإدارة) · `settings` (لضمان ظهور حفظ الإدارة فوراً) · الإعلانات العائمة والتقييمات — سلامة البيانات أولاً
- **تقليم حمولة `/api/settings`**: بيانات `base64` القديمة في سلايدر الوسائط لا تُنقل بعد اليوم إذا كان للعنصر رابط ملف حديث (`/api/media/...`) — كانت تُعاد مع كل تحميل صفحة لكل زائر (النداء `no-store`) — العناصر القديمة بلا رابط تُخدم كما هي (توافق رجعي كامل)
- **robots.txt محدّث**: `Disallow: /api/` للجميع — الروبوتات (بما فيها Google Images والماسحات) كانت تزحف على الوسائط وواجهات API وتستهلك النطاق بلا فائدة — الصفحة الرئيسية تبقى قابلة للفهرسة والمعاينة على واتساب/فيسبوك/تويتر
- **ضغط الصور في المتصفح قبل الرفع** (حماية مستقبلية لقاعدة البيانات): صور الهاتف تُصغّر تلقائياً إلى حد أقصى 1920px وترميز JPEG 0.85 — صورة 4MB تصبح ~300-500KB (**توفير 85-95%**) — الفيديو وGIF المتحرك والصور الصغيرة تمر كما هي، وأي فشل يعيد الملف الأصلي فلا يتعطل الرفع أبداً (اختُبر فعلياً: 1.2MB ← 450KB)
- **نتيجة متوقعة**: الزائر المتكرر ≈ صفر Origin (كاش المتصفح + SW + الحافة) — الزائر الجديد يستهلك الوسائط مرة واحدة لكل منطقة فقط — راقب «Usage → Fast Origin Transfer» في لوحة Vercel

- **الإعدادات بخمس لغات كاملة**: كل الحقول الثلاثية صارت خماسياً (اسم المركز، الشعار النصي، نبذة، العنوان، تصنيفات الخدمات والتكوينات، العبارات الترحيبية، التخصصات) — التركية والإسبانية مثل الفرنسية تماماً
- **سجل التدقيق يُحذف تلقائياً بعد 3 أيام** (TTL في قاعدة البيانات + تنظيف احتياطي) **+ زر تفريغ فوري** في مكانه للإدارة مع نافذة تأكيد
- **تعديل وحذف كل التخصصات**: الافتراضية لم تعد مقفلة — زر تعديل بنموذج خماسي اللغات وزر حذف بنافذة تأكيد للجميع؛ المحذوف من الافتراضية لا يعود عند إعادة التشغيل (رموز ثابتة)
- **صفحة اتصل بنا بالتركية/الإسبانية**: كان العنوان يظهر بالفرنسية وأسماء الأيام بالإنجليزية — صارت بخمس لغات مع سقوط ذكي، وكذلك وثائق المرضى
- **ترجمة شاملة متوازنة**: 862 مفتاحاً × 5 قواميس متطابقة تماماً

## ميزات المنصة (منذ v3.8)

### 1. لوحة إحصائيات حية برسوم بيانية
الحجوزات الشهرية (آخر 6 أشهر حسب الحالة)، الخدمات الأكثر طلباً، منحنى نمو العملاء — Recharts، تحديث تلقائي كل 45 ثانية.

### 2. تصدير البيانات Excel/CSV
الحجوزات، الحسابات، الفواتير — CSV بترميز UTF-8 + BOM يفتح مباشرة في Excel، بعناوين **بلغة واجهة المستخدم** (5 لغات) وبتوقيت الجزائر GMT+1 (Africa/Algiers). من: الإعدادات → الأدوات.

### 3. سجل تدقيق Audit Log
توثيق تلقائي لكل عملية حساسة: من فعل ماذا ومتى ومن أي IP — الدخول (نجاح/فشل/حجب)، المواعيد، الكوبونات، الشهادات، الفواتير، النسخ الاحتياطي، التصدير، الإعدادات، الحسابات. عرض/بحث للإدارة من تبويب الأدوات.

### 4. نسخ احتياطي بضغطة
ملف ZIP كامل: كل مجموعات قاعدة البيانات (JSON) + كل وسائط GridFS + فهرس — تدفقياً دون استهلاك الذاكرة.

### 5. وضع عدم الاتصال (PWA)
Service Worker v3.9: الصفحات المزارة تعمل بلا إنترنت، الوسائط تُخزَّن بعد أول مشاهدة، صفحة «بلا اتصال» أنيقة ثلاثية اللغة عند العجز الكامل. يُسجَّل SW تلقائياً من أول زيارة.

### 6. دخول عبر Google OAuth
زر «الدخول بحساب Google» في بوابة العملاء — **بجانب** الدخول التقليدي بالهاتف/كلمة المرور (لا يُستبدل). أضف مفاتيح GOOGLE في `.env` ويعمل فوراً؛ بدونها يظهر تنبيه واضح وكل شيء آخر يعمل. بعد العودة من Google تظهر رسالة نجاح أو سبب الفشل الصريح، والرابط الدقيق المطلوب في Google Console يظهر للإدارة في: الأدوات → بطاقة دخول Google.

### 7. حماية متقدمة
- حجب محاولات الدخول: 5 فشلات للهاتف → حجب 15 دقيقة (وعتبة IP أعلى = 20 لصعق الهجمات الآلية دون الإضرار بالشبكات المشتركة)
- رؤوس أمان لكل الاستجابات: nosniff، Referrer-Policy، X-Frame-Options، frame-ancestors، Permissions-Policy، HSTS
- توثيق كل محاولة فاشلة/محجوبة في سجل التدقيق

### 8. المساعد الذكي Chatbot
ودجت عائم في كل الصفحات: ردود فورية على الأسئلة الشائعة (حجز، أسعار، خصومات، عن بُعد، تخصصات، تكوينات، موقع…) بخمس لغات + أزرار توجيه مباشر + زر إغلاق يجعل الودجت يختفي كلياً (يعود في زيارة قادمة) + نافذة متجاوبة بمساحة أجوبة كاملة. يعمل بلا خدمات خارجية وبلا تكلفة.

### 9. شهادات وقصص نجاح
صفحة عامة تديرها الإدارة — **سياسة الخصوصية**: الاسم يُحوَّل تلقائياً لصيغة محمية (الأول + حرف) ولا يظهر اسماً كاملاً أبداً للزوار؛ الاسم الحقيقي يبقى سرياً للإدارة. اعتماد/تعديل/حذف + تمييز «قصة نجاح».

### 10. إضافة الموعد للتقويم
زر «التقويم» على بطاقات المواعيد المؤكدة: رابط Google Calendar مباشر + ملف iCal (.ics) قياسي يعمل مع Apple/Outlook مع تذكير قبل ساعة.

### 11. فواتير PDF تلقائية — بالفرنسية دائماً
عند إنهاء الجلسة أو أداء المبلغ تُولَّد فاتورة PDF **بالفرنسية كاملة** بتخطيط منظم (Facture de séance، رقم INV-YYYYMM-XXXXXX، المبالغ، الخصم، الكوبون) بشعار المركز وبياناته، وتُحفظ في GridFS وترتبط بملف العميل — تنزيلها من بطاقة الموعد (للإدارة والأخصائي).

### 12. رموز خصم وعروض (كوبونات)
الإدارة تنشئ كوبونات نسبة % أو مبلغ ثابت مع: تاريخ انتهاء، حد استخدام، أدنى سعر، وصف ثلاثي اللغة. العميل يدخل الكود في خطوة التأكيد → تحقق خادمي كامل → يُخصم المبلغ ويُسجَّل على الموعد والفاتورة، وعدّاد الاستخدام يتزايد تلقائياً.
